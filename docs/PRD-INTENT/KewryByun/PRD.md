## 1. 제품 개요

한국 본사(DSD)가 해외 4개국(중국·일본·베트남·인도네시아) 공장에 전기차용 배터리 셀(2170 원통형)을 주문할 때,
**공장별 생산·재고 제약** 아래에서 **선박 배송 경로**를 계산해 주고, 담당자가 고른 안으로 **주문을 확정·관리**하는 웹 앱이다.

- 사용자: 본사 주문 담당자(관리자)
- UI·메시지 언어: 한국어

## 2. 용어 / 단위

| 용어 | 정의 |
|---|---|
| 셀(Cell) | 배터리 1개 |
| K | 1,000개. 모든 수량은 K 단위로 입력·계산한다 (예: 15,000K = 15,000,000셀) |
| 재고 상한 | 공장 완제품 창고에 보관할 수 있는 최대 수량(K) |
| 일일 최대 생산량 | 공장이 하루에 만들 수 있는 최대 수량(K) |
| 생산원가 | 셀 1개당 원(₩). 공장(국가)마다 다르다 |
| 운항비 | 선박 1척당 하루 임차비. 한국 항만 정박 중에는 0원 |
| 기준 정보(마스터 데이터) | 공장별 생산량·재고 상한·원가, 나라 간 항해 일수, 선박 수·일 운항비 |
| 경로안 | 시뮬레이션이 제시하는 배송 계획 (COST / FAST / NEAR) |

## 3. 기능 요구사항

### 3.1 로그인
- FR-01 로그인하지 않은 사용자는 로그인 화면 외의 모든 화면·API에 접근할 수 없다. **[구현됨]**
- FR-02 담당자는 로그인·로그아웃할 수 있다. 현재 계정은 `admin` 1개이다. **[구현됨]**

### 3.2 주문 입력과 시뮬레이션
- FR-10 담당자는 공장 4곳별 주문 수량(K)을 **직접 배분해 입력**한다. **[구현됨]**
- FR-11 총 수량은 1K 이상 100,000K 이하여야 한다. 위반 시 사유를 알려 주고 계산하지 않는다. **[구현됨]**
- FR-12 시스템은 입력에 대해 **경로안 3가지**를 계산해 보여 준다. 각 안에는 총 소요일, 생산비, 운항비, 총비용, 선박별 일정(방문 국가·도착일·적재량), 공장별 일자별 재고·생산량이 포함된다. **[구현됨]**
  - COST: 운항비 최소 (동률이면 총 일수가 짧은 쪽)
  - FAST: 총 소요일 최소 (동률이면 운항비가 적은 쪽)
  - NEAR: 한국에서 가까운 나라부터 배에 번갈아 배정
- FR-13 계산한 경로를 지도 위 선박 이동 애니메이션 등으로 시각화한다(`CLAUDE.md` 기준). **[구현됨]**
- FR-14 총 주문 수량을 일일 최대 생산량·생산원가·재고 상한을 고려해 공장별로 **자동 배분(추천)**한다. **[확인 필요]** — PPT는 "생산물량을 배분합니다"라고 적었으나 현재는 담당자가 배분량을 입력한다.
- FR-15 고객사·필요 납기를 입력받고 경로 계산에 반영한다. **[미구현]**

### 3.3 주문 확정
- FR-20 담당자는 3안 중 하나를 선택하고 메모(1,000자 이하)를 붙여 주문을 확정한다. **[구현됨]**
- FR-21 확정되는 계획은 서버가 **같은 입력으로 다시 계산한 결과**여야 한다(클라이언트가 보낸 계산값을 신뢰하지 않는다). **[구현됨]**
- FR-22 시뮬레이션 이후 기준 정보가 바뀌었다면 확정을 거부하고 다시 시뮬레이션하도록 안내한다(충돌). **[구현됨]**
- FR-23 확정된 주문에는 당시 기준 정보와 계획이 함께 보존되어, 이후 기준 정보를 바꿔도 **기존 주문의 계획은 변하지 않는다**. **[구현됨]**

### 3.4 주문 목록 / 상세
- FR-30 확정된 주문은 목록에 등록되고, 상태별 건수와 상태 필터를 제공한다. **[구현됨]**
- FR-31 주문 상세에서 수량·선택한 경로안·비용·메모·상태 변경 이력을 볼 수 있다. **[구현됨]**

### 3.5 주문 상태 관리

| 상태 | 의미 (PPT 기준) |
|---|---|
| 확정 | 고객사와 구두로 확정한 상태 |
| 진행 | 계약서 작성 후 공장 생산·운영을 시작한 상태 |
| 완료 | 생산이 끝나 물량이 모두 한국에 입고된 상태 (종료 상태) |
| 취소 | 사정으로 취소된 상태 (종료 상태) |

- FR-40 허용되는 전이는 **확정→진행, 확정→취소, 진행→완료, 진행→취소**뿐이다. 그 외는 거부한다. **[구현됨]**
- FR-41 완료·취소는 최종 상태로, 더 바꿀 수 없다. **[구현됨]**
- FR-42 모든 상태 변경은 누가·언제·어떤 상태에서 어떤 상태로 바꿨는지 이력으로 남긴다. **[구현됨]**
- FR-43 화면에서 본 시점 이후 다른 사용자가 주문을 먼저 바꿨다면 상태 변경을 거부하고 새로 고침을 안내한다(충돌). **[구현됨]**
- FR-44 취소된 주문은 **"취소" 상태로 목록·상세에서 확인**할 수 있어야 한다(PPT 기준). **[확인 필요]** — 현재 코드는 취소 시 주문을 삭제하고 오류 화면이 뜬다. 사실 관계와 선택지는 `INTENT.md` §6-1.

### 3.6 기준 정보 관리
- FR-50 담당자는 공장별 일일 최대 생산량·재고 상한·셀당 원가, 나라 간 항해 일수(전 구간), 선박 수(1~4척), 척당 일 운항비(억 원)를 수정할 수 있다. **[구현됨]**
- FR-51 입력값이 하나라도 올바르지 않으면 **아무것도 저장하지 않고** 모든 오류 사유를 모아 알려 준다. **[구현됨]**
- FR-52 저장에 성공하면 이후 시뮬레이션부터 반영된다. **[구현됨]**
- FR-53 국가별 공장 운영비를 관리하고 비용에 반영한다. **[미구현]**

## 4. 비즈니스 규칙 (경로 계산)

계산 규칙은 서비스의 핵심이며 임의로 바꾸지 않는다.

- BR-01 모든 공장은 **0일차에 동시에** 생산을 시작한다.
- BR-02 하루 생산량 = min(일일 최대 생산량, 재고 상한 − 현재 재고, 남은 주문량).
- BR-03 선박은 도착한 시점의 재고를 **전량** 싣는다. 한 나라는 **한 척의 배만** 방문한다.
- BR-04 한 나라의 방문 횟수 = 올림(주문량 / 재고 상한). 마지막 방문 전까지는 재고 상한만큼, 마지막 방문은 나머지를 싣는다.
- BR-05 여러 번 수거해야 하면 한국에 들러 내려놓고 다시 출항한다(왕복을 나눈다).
- BR-06 선박은 재고가 채워지는 날에 맞춰 **늦게 출항**한다. 한국 정박·대기는 **무료**이다.
- BR-07 **총비용 = 생산비 + 운항비**
  - 생산비 = 주문 수량(K) × 1,000 × 공장별 셀당 원가
  - 운항비 = 선박 항해 일수 합계 × 척당 일 운항비 (정박 일수 제외)
- BR-08 선박은 1~4척이며, 사용 척수는 주문 대상 국가 수를 넘지 않는다.
- BR-09 선박의 컨테이너 적재량은 충분하다고 가정한다. 창고의 배터리는 필요한 만큼 실을 수 있다. (PPT)
- BR-10 수거량이 그 시점의 재고와 다르거나 주문 수량을 모두 수거하지 못하는 계획은 오류이며 결과로 내보내지 않는다.

## 5. 비기능 요구사항

- NFR-01 **동시성**: 주문 확정은 기준 정보 버전, 상태 변경은 주문 버전으로 낙관적 충돌을 감지한다. 충돌은 API에서 409로 응답한다.
- NFR-02 **오류 응답**: 잘못된 입력은 400과 사유로 응답한다. 비로그인 API 호출은 401이다.
- NFR-03 **금액**: 저장은 원 단위, 화면 입력·표시는 억 원 단위로 한다. 원 단위로 떨어지지 않는 값은 거부한다.
- NFR-04 **이력 보존**: 확정 주문의 계획과 상태 변경 이력은 보존한다.
- NFR-05 **자동 검증**: 경로 계산 단위 테스트(`PlannerTest`)와 주문 흐름 테스트(`OrderFlowTests`)가 통과해야 한다.
