# INTENT — 왜 이렇게 만들었나, 무엇을 지켜야 하나

> PRD.md가 "무엇을 해야 하나"라면 이 문서는 "왜 그렇게 되어 있나"와 "바꿀 때 무엇을 지켜야 하나"를 적는다.
> 핵심 의도만 담았다. 의도는 현재 앱의 동작에서 **짐작해서 정리한 것**이며 만든 사람에게 직접 확인한 것이 아니므로 근거를 구분해 표시한다.

## 1. 한 줄 의도

**"최적 경로를 자동으로 실행"하는 것이 아니라, 담당자가 비용과 일정을 비교해 선택하도록 돕고, 선택한 결과가 나중에 바뀌지 않게 보존하는 도구.** [추정]

- 근거: 안을 하나만 내놓지 않고 성격이 다른 3가지를 보여 준다. 그중 하나(가까운 곳부터)는 일부러 최적이 아닌 단순한 비교 기준이다. 확정은 사람이 직접 누른다. [현재 앱]

| I6 | **변경 이력은 주문이 지워져도 남긴다** | 취소하면 주문은 지워지지만 상태 변경 이력은 남는다. | [현재 앱] 동작 / [추정] 의도 |

## 3. 바꿀 때 지킬 방향

| ID | 방향 |
| --- | --- |
| G1 | 주문을 확정할 때는 **항상 시스템이 다시 계산**한다. 화면에서 넘어온 계산 결과를 믿는 방식으로 바꾸지 않는다. (I2) |
| G2 | 기준값이 바뀌면, 그 전에 본 시뮬레이션으로는 **확정할 수 없다.** 기준값을 바꾸는 어떤 기능을 추가하더라도 마찬가지다. (I4) |
| G3 | 주문 상태는 **정해진 순서로만** 바뀌고, 바뀔 때마다 **이력을 남긴다.** 동시에 바꾸면 먼저 한 사람이 우선이다. (I5) |
| G4 | 확정된 주문은 이후 **어떤 변경이 있어도 확정 당시의 모습 그대로** 보여야 한다. 계획에 담는 항목을 바꿀 때는 이미 확정된 기존 주문도 계속 정상으로 보이는지 확인한다. (I3) |
| G5 | 경로 계산 규칙을 바꾸면 PRD §5의 예시 숫자도 함께 갱신한다. "배가 실은 양의 합 = 주문량", "한 나라는 한 척", "재고는 상한 이하" 세 조건과, "운항비 최소"·"가장 빠르게"가 **비길 때의 우선순위**(PRD §5-10)는 유지한다. |
| G6 | 새 기능도 **로그인한 사람만** 쓸 수 있어야 한다. |

## 5. 결정이 필요한 점 (미결)

1. **[미결] 취소한 주문을 남길 것인가?**
   - 설명 자료는 취소를 하나의 상태로 본다. 현재 앱은 주문을 지운다. 목록의 "취소" 버튼은 지워진 주문이 없으므로 항상 0건으로 나올 것으로 보인다(이력만 남음).
   - 선택지: (a) 지우는 방식을 유지하고 "취소" 버튼을 없앤다, (b) 주문은 남기고 상태만 "취소"로 바꾼다.
   - 영향: 변경 이력을 보존하는 방식(I6), 취소 직후 화면에서 보이는 모습.
2. **[미결] 생산 물량을 시스템이 배분할 것인가?** 설명 자료는 시스템이 배분하고, 현재는 담당자가 입력한다. 자동 배분이 들어오면 수량 입력 방식이 바뀐다.
3. **[미결] 공장 운영비를 어떻게 반영할 것인가?** 하루 단위인지, 주문 건당인지, 월 고정인지에 따라 최적 경로와 3가지 안의 비교 결과가 달라진다.
4. **[미결] 고객사·납기를 어떻게 쓸 것인가?** 입력만 받을지, 납기를 넘기는 경로를 걸러 주거나 경고할지.
5. **[미결] "완료"의 기준.** 관리자가 직접 바꾸게 둘지, 배가 한국에 도착하는 일정과 연결할지.
6. **[미결] 로그인과 권한.** 계정 하나가 임시인지, 담당자와 관리자 역할을 나눌지. 설명 자료는 "관리자가 상태를 변경"한다고 한다.
7. **[미결] 생산원가 허용 범위.** 설명 자료는 500~1,000원 수준이고 기본값 중 인도네시아는 450원이다. 입력 제한을 둘지.
