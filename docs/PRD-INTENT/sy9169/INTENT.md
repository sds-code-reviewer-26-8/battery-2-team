# INTENT — 왜 이렇게 만들었나, 무엇을 지켜야 하나

> PRD.md가 "무엇을 해야 하나"라면 이 문서는 "왜 그렇게 되어 있나"와 "바꿀 때 무엇을 지켜야 하나"를 적는다.
> 설계 의도는 현재 앱이 하도록 되어 있는 동작과 그 안의 설명 문구를 읽고 **짐작해서 정리한 것**이다. 만든 사람에게 직접 확인한 것이 아니므로 근거를 구분해 표시한다.

## 1. 한 줄 의도

**"최적 경로를 자동으로 실행"하는 것이 아니라, 담당자가 비용과 일정을 비교해 선택하도록 돕고, 선택한 결과가 나중에 바뀌지 않게 보존하는 도구.** [추정]

- 근거: 안을 하나만 내놓지 않고 성격이 다른 3가지를 보여 준다. 그중 하나(가까운 곳부터)는 일부러 최적이 아닌 단순한 방식이다. 확정은 사람이 직접 누른다. [현재 앱]

| I6 | **상태 규칙을 한 곳에서 정의** | 어떤 상태에서 어떤 상태로 바꿀 수 있는지가 하나의 기준표에만 있고, 화면의 버튼도 같은 기준표를 따른다 | 같은 규칙을 여러 곳에 따로 적지 않는다 | [현재 앱] |
| I7 | **계산 규칙을 화면·저장과 분리** | 경로 계산은 저장이나 화면과 무관하게 기준값과 수량만으로 결과를 낸다 | 같은 수량·같은 기준값이면 언제나 같은 결과가 나오게 유지한다. 계산 부분에 화면·저장 관련 동작을 섞지 않는다 | [현재 앱] |

| I9 | **오류를 모아서 한 번에 알림** | 기준값 저장 시 모든 입력을 검사해 잘못된 곳을 전부 알려 주고, 하나라도 틀리면 **아무것도 저장하지 않는다** | 일부만 저장되는 일이 없어야 한다 | [현재 앱] |
| I10 | **금액은 원 단위로 보관, 화면은 억 원** | 화면은 억 원으로 보여 주고 내부에서는 원 단위로 계산한다. 하루 운항비가 원 단위로 떨어지지 않으면 거절한다 | 소수점이 남는 금액을 저장하지 않는다 | [현재 앱] |

## 3. 바꿀 때 지킬 방향

| ID | 방향 |
| --- | --- |
| G1 | 주문을 확정할 때는 **항상 시스템이 다시 계산**한다. 화면에서 넘어온 계산 결과를 믿는 항목을 추가하지 않는다. (I2) |
| G2 | 기준값을 바꾸는 기능은 반드시 **기준값 번호를 올린다.** (I4) |
| G3 | 주문 상태를 바꾸는 기능은 **변경 번호 비교와 이력 기록을 함께** 한다. 상태 규칙은 기준표 한 곳에서만 고친다. (I5, I6) |
| G4 | 계획에 담기는 항목을 바꾸면, **확정된 주문을 보여 주는 화면(표와 지도 애니메이션)**과 **이미 확정된 기존 주문**이 계속 정상으로 보이는지 함께 확인한다. (I3) |
| G5 | 계산 규칙을 바꾸면 기대하는 숫자(중국 400K → 2일, 베트남 2,000K → 15일, 일본 4,500K → 2,000/2,000/500)도 함께 갱신한다. 세 가지 조건(실은 양 = 주문량, 한 나라는 한 척, 재고 ≤ 상한)은 유지한다. |
| G6 | "운항비 최소"와 "가장 빠르게"에서 **비기는 경우의 우선순위**(운항비 → 일수, 일수 → 운항비)를 바꾸지 않는다. 바뀌면 같은 입력에 다른 안이 나온다. |
| G7 | 새 기능과 화면도 **로그인한 사람만** 쓸 수 있어야 하고, 오류 안내 방식을 지금과 같게 유지한다(동시 변경·기준값 변경은 "다시 시도" 안내, 그 외는 잘못된 입력 안내). |
| G8 | 업무 규칙은 화면이 아니라 **업무 규칙을 모아 둔 곳**에서만 처리한다. 화면에 규칙을 새로 넣지 않는다. |
| G9 | 공장·배를 늘리는 변경은 계산 시간이 얼마나 늘어나는지 **먼저 확인**한다. |

## 5. 결정이 필요한 점 (미결)

1. **[미결] 취소한 주문을 남길 것인가?**
   - 설명 자료는 취소를 하나의 상태로 본다. 현재 앱은 주문을 지운다. 목록의 "취소" 버튼은 지워진 주문이 없으므로 항상 0건으로 나올 것으로 보인다(이력만 남음).
   - 선택지: (a) 지우는 방식을 유지하고 "취소" 버튼을 없앤다, (b) 주문은 남기고 상태만 "취소"로 바꾼다.
   - 영향: 변경 이력을 보존하는 방식(I11), 취소 직후 화면 문제(§4), 취소 관련 확인 항목.
2. **[미결] 생산 물량을 시스템이 배분할 것인가?** 설명 자료는 시스템이 배분하고, 현재는 담당자가 입력한다. 자동 배분이 들어오면 수량 입력 방식과 시뮬레이션의 입력이 바뀐다.
3. **[미결] 공장 운영비를 어떻게 반영할 것인가?** 하루 단위인지, 주문 건당인지, 월 고정인지에 따라 최적 경로와 3가지 안의 비교 결과가 달라진다.
4. **[미결] 고객사·납기를 어떻게 쓸 것인가?** 입력만 받을지, 납기를 넘기는 경로를 걸러 주거나 경고할지.
5. **[미결] "완료"의 기준.** 관리자가 직접 바꾸게 둘지, 배가 한국에 도착하는 일정과 연결할지.
6. **[미결] 로그인과 권한.** 계정 하나가 임시인지, 담당자와 관리자 역할을 나눌지. 설명 자료는 "관리자가 상태를 변경"한다고 한다.
7. **[미결] 생산원가 허용 범위.** 설명 자료는 500~1,000원 수준이고 기본값 중 인도네시아는 450원이다. 입력 허용 범위(1원~1억 원)를 좁힐지.
