# PRD — 배터리 주문 시뮬레이터 (팀 통합본)

> 이 문서는 **바뀌지 않을 핵심 요구사항**만 적는다.
> 공장별 생산량·항해 일수·원가처럼 운영 중 바뀌는 값은 **기준값(마스터 데이터)**이므로 이 문서에 고정하지 않는다. 예시 숫자는 처음 설정된 기본값일 뿐이다.

## 1. 배경과 목표

- 한국 본사를 둔 DSD는 전기차용 원통형 배터리 셀(2170)을 **중국·일본·베트남·인도네시아 4개국의 자체 공장**에서 생산해 공급한다. [설명]
- 공장마다 **하루 최대 생산량**, **재고 창고 용량**, **셀당 생산원가**가 다르다. 완제품은 공장 창고에 쌓이고 출고 전까지 보관된다. [설명]
- 완성된 셀은 **1~4척의 화물선을 빌려** 한국으로 운송한다. 배 임차료는 척당 하루 약 1억 원이고, **한국 항만에 정박해 있는 동안은 비용이 없다.** 선박 적재량은 충분하다고 본다. [설명]
- 주문(예: 15,000K)이 들어오면 **어느 공장에 얼마를 맡기고 배를 어떻게 돌릴지**를 정해야 한다. 두 결정이 얽혀 있어 사람이 바로 판단하기 어렵다. [설명]

**목표:** 주문 수량을 넣으면 배 운영 계획을 **같은 기준으로 비교할 수 있는 3가지 안**으로 보여 주고, 담당자가 하나를 골라 **주문으로 확정**하고 이후 **진행 상태를 관리**할 수 있게 한다. 최종 선택은 사람이 한다.

## 3. 용어와 단위

| 용어 | 뜻 |
| --- | --- |
| K | 셀 1,000개. 주문 수량의 단위 (15,000K = 1,500만 셀. 차량 1대에 약 4K가 필요하다 [설명]) |
| 기준값(마스터 데이터) | 계산의 바탕이 되는 값: 공장(하루 최대 생산량·재고 상한·셀당 원가), 항로(나라 쌍별 항해 일수), 배(척수·하루 운항비) |

| 일차 | 주문일을 0일로 센 날짜 |
| 왕복 | 한국에서 출항해 여러 나라를 들르고 한국으로 돌아오는 한 바퀴 |
| 금액 단위 | 화면에는 억 원으로 표시한다 |

## 5. 계산 규칙 (바뀌지 않는 규칙)

1. **동시 생산:** 주문 첫날(0일차)에 모든 공장이 동시에 생산을 시작한다.
2. **하루 생산량** = 하루 최대 생산량, 창고에 남은 공간, 남은 주문량 중 가장 작은 값. 창고가 가득 차면 배가 물건을 가져갈 때까지 생산이 멈춘다.
3. **수거:** 배는 도착한 시점에 쌓여 있는 재고를 **전부** 싣는다.
4. **한 나라는 한 척의 배만 방문한다.** 사용하는 배의 수는 주문이 있는 나라의 수를 넘지 않는다.
5. **방문 횟수** = 올림(주문량 ÷ 재고 상한). 마지막 방문 전까지는 상한만큼, 마지막에는 나머지를 싣는다.
6. 여러 번 수거할 때 배는 **한국에 내려놓고 다시 출항**한다.
7. 배는 재고가 채워지는 날에 맞춰 **늦게 출항**한다. 한국에서의 대기는 무료이므로, 일찍 나가 기다리기보다 늦게 나가는 편이 이득이다. [설명]
8. **비용**
   - 생산 원가 = 수량(K) × 1,000 × 나라별 셀당 원가
   - 운항비 = 배들이 실제로 항해한 일수의 합 × 척당 하루 운항비 (한국에서 기다린 날은 제외)
   - 총 비용 = 생산 원가 + 운항비 (공장 운영비는 F12가 구현되기 전까지 포함되지 않음)
9. **총 소요일** = 마지막 배가 한국에 돌아오는 날.
10. **3가지 안의 정의**
    - 운항비 최소: 운항비가 가장 낮은 안. 같으면 더 빠른 쪽
    - 가장 빠르게: 총 소요일이 가장 짧은 안. 같으면 더 저렴한 쪽
    - 가까운 곳부터: 한국에서 가까운 나라부터 배에 번갈아 맡기는 **단순한 비교 기준 안**(최적은 아님)
11. **항상 지켜져야 하는 조건:** 어떤 안이든 (a) 배가 실은 양의 합은 나라별 주문량과 같고, (b) 재고는 창고 상한을 넘지 않으며, (c) 총 비용은 생산 원가와 운항비의 합이다.
12. 배의 적재량은 충분하다고 본다. 창고의 배터리는 필요한 만큼 실을 수 있다. [설명]

**숫자 예시** (기본 기준값, 배 1척, 하루 운항비 1억 원) [현재 앱]

| 주문 | 결과 |
| --- | --- |
| 베트남 2,000K | 생산 10일, **5일차 출항**(재고가 찰 때 맞춰), 10일차 도착, **15일차 귀환**, 운항비 10억 원 |
| 일본 4,500K (재고 상한 2,000K) | 방문 3번: 2,000 / 2,000 / 500 |

## 6. 주문 상태

| 상태 | 업무 의미 [설명] | 다음에 바꿀 수 있는 상태 |
| --- | --- | --- |
| 확정 | 고객사와 소통해 **구두로 확정**된 상태. 주문의 최초 상태 | 진행, 취소 |
| 진행 | **계약서 작성 후** 공장 생산과 운영을 시작한 상태 | 완료, 취소 |
| 완료 | 생산이 끝나고 **물량이 한국에 모두 들어온** 상태 | 없음 (최종) |
| 취소 | 어떤 사정으로 취소된 상태. **확정·진행 중에만** 가능 | 없음 (최종) |

- 건너뛰기(예: 확정 → 완료)와 되돌리기는 없다. [현재 앱]
- 취소하면 주문은 **지워지지 않고 상태만 "취소"로 바뀌며**, 변경 기록이 남는다. 취소는 더 바꿀 수 없는 최종 상태이고 상세·이력을 계속 볼 수 있다. [현재 앱, PR #28부터] §10-1
- **[확인 필요]** "완료"는 지금 관리자가 직접 바꾸는 값이며, 실제 물량 입고와 연결되어 있지 않다. §10-5

## 7. 데이터 신뢰 요구사항

| ID | 요구사항 | 근거 |
| --- | --- | --- |

| D3 | 확정할 때 화면에 보인 계산 결과를 그대로 저장하지 않고, **시스템이 같은 수량으로 다시 계산**해서 저장한다. | [현재 앱] |
| D4 | 주문 상태는 정해진 순서로만 바뀐다. 두 사람이 같은 주문을 동시에 바꾸려 하면 **먼저 바꾼 사람의 변경이 적용되고** 나중 사람에게는 새로 고침 후 다시 시도하라고 안내한다. | [현재 앱] |
| D5 | 기준값 입력에 잘못된 곳이 하나라도 있으면 **아무것도 저장하지 않고** 잘못된 곳을 모두 알려 준다. | [현재 앱] |
| D6 | 계산 결과가 맞는지 스스로 점검하고, 맞지 않으면 틀린 결과를 보여 주는 대신 중단한다. | [현재 앱] |

## 8. 입력 제약

| 항목 | 허용 범위 |
| --- | --- |
| 나라별 주문 수량 | 0 이상 |
| 총 주문 수량 | 1K 이상 100,000K 이하. 어기면 이유를 알려 주고 계산하지 않는다 |
| 배 척수 | 1~4척 |
| 척당 하루 운항비 | 0보다 큼 |

세부 입력 한도(공장 생산량, 원가, 항해 일수, 메모 길이 등)는 운영 중 바뀔 수 있는 값이라 이 문서에 고정하지 않는다.

## 9. 화면 범위와 범위 밖

**화면:** 로그인 / 주문 목록 / 주문 추가(수량 입력 → 시뮬레이션 → 확정, 지도에서 배 이동 확인) / 주문 상세(확정 당시 계획, 상태 변경, 변경 이력) / 기준값(마스터 데이터). [현재 앱]

**범위 밖 (현재 없음)**
- 고객사·납기 관리, 공장 운영비 계산 (F4, F12)
- 생산 물량의 자동 배분 (F3)
- 사용자별 계정과 권한
- 확정한 주문 내용의 수정 (불가)
- 실제 선박 위치 추적, 항만 혼잡, 날씨 등 현실 변수
- 실제 생산·선박 시스템과의 연동, 통화 환산·세금·관세
