# PRD — 배터리 해상 운송 경로 계획 및 주문 관리

> 이 문서는 **바뀌지 않을 핵심 요구사항**만 적는다.
> 값(생산량, 항해 일수 등)처럼 운영 중 바뀌는 것은 "마스터 데이터"로 관리하며 이 문서에 고정하지 않는다.
> 목적·설계 의도·변경 시 지킬 방향은 `INTENT.md`에 있다.

- 작성일: 2026-10-21
- 기준: 저장소 `main` (코드에서 확인한 사실만 기재)

## 1. 문제와 목표

여러 나라의 공장에서 만든 배터리를 **배로 한국에 모아 와야** 한다. 생산 속도, 공장 창고 한도, 나라 간 항해 일수, 배 운항비가 얽혀 있어 어떻게 도는 것이 좋은지 사람이 바로 판단하기 어렵다.

**목표:** 나라별 필요 수량을 입력하면 배의 운항 계획을 **3가지 안**으로 계산해 비교하게 하고, 선택한 안을 **주문으로 확정·관리**할 수 있게 한다.

## 2. 사용자

- 배터리 수급·운송 계획을 세우고 주문을 확정하는 **담당자**
- 로그인한 사용자만 사용한다.

## 3. 핵심 기능 요구사항

| ID | 요구사항 |
|---|---|
| F1 | 나라별 필요 수량(K)을 입력해 시뮬레이션을 실행할 수 있다. |
| F2 | 시뮬레이션은 **3가지 안**(운항비 최소 / 가장 빠르게 / 가까운 곳부터)을 한 번에 보여 준다. 각 안은 총 소요일, 생산비, 운항비, 합계 비용, 배별 일정, 나라별 일별 재고·생산량을 포함한다. |
| F3 | 시뮬레이션은 **미리보기**다. 확정하기 전에는 아무것도 저장되지 않는다. |
| F4 | 사용자가 한 안을 골라 메모와 함께 **주문을 확정**할 수 있다. |
| F5 | 확정된 주문을 목록(상태별 필터·건수)과 상세로 조회할 수 있다. 상세에서 확정 당시의 계획을 다시 볼 수 있다. |
| F6 | 주문 **상태**를 정해진 규칙으로만 변경할 수 있고, 모든 변경은 **이력**(일시, 이전·새 상태, 변경한 사람)으로 남는다. |
| F7 | 계산에 쓰는 기준 정보(**마스터 데이터**: 공장, 배, 항로)를 화면에서 조회·수정할 수 있다. |

## 4. 도메인 규칙 (계산의 불변 규칙)

1. **공장·나라:** 한국이 도착지이고, 생산 공장은 그 밖의 나라에 있다. 공장은 나라당 하나다.
2. **동시 생산:** 주문 첫날(0일차)에 모든 공장이 동시에 생산을 시작한다.
3. **하루 생산량** = min(하루 최대 생산량, 창고 한도 − 현재 재고, 남은 주문량). 창고가 차면 생산이 멈춘다.
4. **수거:** 배는 도착 시점의 재고를 모두 싣는다.
5. **한 나라는 한 척의 배만 방문한다.**
6. **방문 횟수** = 올림(주문량 ÷ 창고 한도). 마지막 방문 전까지는 창고 한도만큼, 마지막은 나머지를 싣는다.
7. 여러 번 수거할 때 배는 **한국에 내려놓고 다시 출항**한다(왕복을 나눈다).
8. 배는 필요한 재고가 채워지는 날에 맞춰 출항한다. **한국에서의 대기는 무료**다.
9. **비용:** 합계 = 생산비 + 운항비.
   - 생산비 = 주문 수량 × 나라별 개당 원가 (수량 단위 K = 1,000개)
   - 운항비 = 배들이 실제 항해한 일수의 합 × 척당 하루 운항비
10. **3가지 안의 정의**
    - 운항비 최소: 운항비가 가장 낮은 안(같으면 더 빠른 쪽)
    - 가장 빠르게: 완료일이 가장 이른 안(같으면 더 저렴한 쪽)
    - 가까운 곳부터: 한국에서 가까운 나라부터 배에 차례로 나눠 배정하는 비교 기준용 안
11. 총 소요일은 **마지막 배가 한국에 돌아오는 날**이다.
12. **입력 제약:** 나라별 수량은 0 이상, 총 수량은 1K 이상 100,000K 이하다. 배는 1~4척이다.

## 5. 주문 상태 규칙

```
확정 ──▶ 진행 ──▶ 완료
 │        │
 └──▶ 취소 ◀──┘
```

- 최초 상태는 항상 **확정**이다.
- 확정 → 진행·취소, 진행 → 완료·취소만 허용한다. 건너뛰기와 되돌리기는 없다.
- 완료와 취소는 **최종 상태**다.

## 6. 데이터 무결성 요구사항

| ID | 요구사항 |
|---|---|
| D1 | **확정된 주문은 확정 당시의 수량·기준 정보·경로·일별 생산을 그대로 보존**한다. 이후 마스터가 바뀌어도 확정 주문은 바뀌지 않는다. |
| D2 | 시뮬레이션 이후 마스터 데이터가 바뀌었다면 **확정을 거부**하고 다시 시뮬레이션하게 한다. |
| D3 | 확정 시 **서버가 같은 입력으로 다시 계산**한다. 화면이 보낸 계산 결과를 신뢰하지 않는다. |
| D4 | 여러 사용자가 동시에 같은 주문을 바꿀 때 **늦게 요청한 쪽을 거부**하고 이유를 알린다. |
| D5 | 마스터 값에 하나라도 잘못된 값이 있으면 **아무것도 저장하지 않고** 모든 이유를 알린다. |
| D6 | 계산 결과는 일별 생산·재고와 **수거량이 정확히 일치**해야 한다. 어긋나면 결과를 내지 않는다. |

## 7. 접근 통제

- 로그인하지 않으면 로그인 화면 외에는 사용할 수 없다.
- 로그인하지 않은 데이터 요청(API)은 거절한다.

## 8. 화면 범위

로그인 / 주문 목록 / 주문 추가(수량 입력 → 시뮬레이션 결과 → 확정) / 주문 상세(상태 변경·이력·계획 재현) / 마스터 데이터.

## 9. 범위 밖 (이 PRD가 다루지 않는 것)

- 실제 선박 위치 추적, 항만 혼잡, 날씨 등 현실 변수
- 복수 계정·권한 등급, 외부 시스템 연동
- 확정 후 계획 수정(변경이 필요하면 새 주문으로 다룬다)

## 10. 단위

- 수량: K(1,000개), 비용 표시: 억 원, 기간: 일, 시각: 주문일(0일차)부터 센 일수
