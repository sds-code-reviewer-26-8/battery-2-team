# HTML Report Generator

프로젝트 소스를 읽고, 처음 보는 사람도 5분 안에 "이 시스템이 무엇을 하고 어떻게 돌아가는지"를
파악할 수 있는 **파일 하나짜리 HTML 문서**를 만든다.

## 결과물 원칙

- **파일 하나로 끝난다.** CSS와 JS는 모두 인라인으로 넣는다. 외부 CDN, 외부 폰트, 외부 이미지를
  쓰지 않는다. 사내망이나 오프라인에서 더블클릭만으로 열려야 하기 때문이다.
- **소스에서 읽은 사실만 쓴다.** 추측한 기능, 소스에 없는 수치는 넣지 않는다. 확인이 안 되면
  "소스에서 확인되지 않음"이라고 쓰는 편이 틀린 정보보다 낫다.
- **한국어로 쓴다.** 클래스명, URL, 설정 키 같은 식별자는 원문 그대로 `code`로 표시한다.
- **저장 위치**는 사용자가 지정하면 그곳, 아니면 `docs/<프로젝트명>-report.html`.

## 절차

1. **구조 파악** — 빌드 파일(`build.gradle*`, `pom.xml`, `package.json` 등)로 언어/프레임워크/버전을
   확인하고, 설정 파일(`application.properties|yml`)에서 DB, 포트 등 실행 환경을 읽는다.
2. **기능 추출** — 컨트롤러/라우터에서 URL과 HTTP 메서드를 뽑고, 각 URL이 어떤 화면(템플릿)이나
   JSON을 돌려주는지 정리한다. 서비스 계층의 public 메서드로 핵심 비즈니스 로직을 파악한다.
3. **도메인 모델 정리** — 엔티티/레코드의 필드와 관계, enum 값과 상태 전이 규칙을 표로 만든다.
   enum에 `next()` 같은 전이 메서드가 있으면 상태도(텍스트 또는 SVG)로 그린다.
4. **핵심 알고리즘/규칙** — 시뮬레이션, 계산, 검증 같은 핵심 로직이 있으면 Javadoc과 코드 주석을
   근거로 규칙을 bullet로 요약한다. 코드 전체를 옮겨 적지 않는다.
5. **초기 데이터** — `DataInitializer`, seed SQL, `initDefaults()` 같은 곳에서 기본 데이터가
   들어가면 표로 넣는다. 리뷰어가 화면을 열었을 때 보이는 값과 문서가 일치해야 한다.
6. **템플릿 채우기** — `assets/template.html`을 읽어 `<!-- SECTION: ... -->` 자리를 채운다.
   템플릿의 CSS 토큰과 레이아웃은 그대로 두고 내용만 넣는다. 필요 없는 섹션은 통째로 지운다.
7. **검증** — 저장 후 브라우저(또는 Playwright)로 열어 깨진 표, 빈 섹션, 가로 스크롤이 없는지
   확인한다. 가능하면 스크린샷을 찍어 사용자에게 보여준다.

## HTML 섹션 (이 순서를 지킨다)

1. **헤더** — 프로젝트명, 한 줄 설명, 생성일, 기술 스택 배지
2. **개요** — 이 시스템이 해결하는 문제와 주요 사용자. 3~5문장.
3. **주요 기능** — 카드 형태. 기능명 + 2줄 설명 + 진입 URL.
4. **화면 / API 흐름** — 표: 메서드, URL, 역할, 반환(템플릿명 또는 JSON).
5. **도메인 모델** — 엔티티별 표(필드, 타입, 의미). enum은 값과 라벨, 상태 전이 포함.
6. **핵심 규칙 / 알고리즘** — bullet 요약. 있을 때만.
7. **기본 데이터** — 초기 마스터 값 표. 있을 때만.
8. **실행 방법** — 빌드/실행 명령, 접속 URL, 로그인 계정(소스에 있을 때만), DB 위치.
9. **소스 구조** — 패키지/폴더 트리와 각 폴더의 역할 한 줄.

## 스타일 규칙

- 템플릿의 `:root` 색 토큰만 사용한다. 라이트/다크 모드 모두에서 읽혀야 하므로 색을
  직접 하드코딩하지 않는다.
- 표는 `<table>`로 쓰고 첫 열에 식별자를 둔다. 모바일 폭(390px)에서는 표가 가로 스크롤되도록
  `.table-wrap`으로 감싼다. 페이지 전체가 가로 스크롤되면 안 된다.
- 섹션마다 `<h2>`에 `id`를 붙이고 상단 목차에서 앵커로 연결한다.
- 코드 식별자는 `<code>`, 명령어는 `<pre><code>` 블록.
- 이모지와 장식용 이미지는 쓰지 않는다. 사내 문서 톤을 유지한다.

## 좋은 결과물의 예

**입력**: "battery-2-team 프로젝트 소개 HTML 만들어줘"
**출력**: `docs/battery-2-team-report.html`
- 헤더: "Battery 주문·운송 시뮬레이션", Spring Boot 4.1 / Java 17 / H2 배지
- 주요 기능 카드 4개: 주문 시뮬레이션, 주문 확정, 주문 상태 관리, 마스터 데이터 관리
- 화면 흐름 표 12행 (`GET /orders`, `POST /api/simulate` …)
- `OrderStatus` 상태 전이: 확정 → 진행 → 완료, 각 단계에서 취소 가능
- 기본 데이터 표: 공장 4개국의 일 최대 생산량 / 재고 상한 / 단가, 항로 일수 10개

## 피해야 할 것

- 소스를 읽지 않고 일반적인 Spring Boot 설명으로 채우기
- 섹션 제목만 있고 내용이 "TBD"인 빈 섹션 남기기
- 클래스 전체 코드를 HTML에 붙여넣기 (요약이 목적이다)
- 외부 CSS 프레임워크(Tailwind CDN, Bootstrap CDN) 링크
