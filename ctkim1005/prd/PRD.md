| 항목 | 내용 |
|---|---|

## 1. 개요

해외 4개국(중국·일본·베트남·인도네시아) 공장에서 배터리를 생산하고 보유 선박으로 한국까지 운송하는 과정을 일 단위로 시뮬레이션한다. 사용자는 나라별 주문 수량을 입력해 경로안을 비교하고, 하나를 골라 주문을 확정한 뒤 상태를 관리한다.

## 2. 사용자

- **담당자**: 단일 관리 계정으로 로그인해 시뮬레이션·주문 확정·상태 변경·마스터 수정을 모두 수행한다.
- 역할 구분은 없다. 사내 소수 인원이 함께 쓰는 도구다.

## 3. 기능 요구사항

### 3.1 로그인
- 아이디/비밀번호로 로그인한다. 계정은 하나이며 소스에 고정되어 있다.
- 로그인하지 않으면 `/login`과 정적 자원을 제외한 모든 화면에 접근할 수 없다.
- 로그아웃하면 세션이 무효화된다.

### 3.2 마스터 데이터 관리
- 공장별로 **하루 최대 생산량(K)**, **재고 상한(K)**, **단가(원)** 를 수정할 수 있다.
- 나라 간 **항로 일수**를 수정할 수 있다. 한 구간은 방향과 무관하게 하나의 값이다.
- **보유 선박 수**와 **선박 1척 1일 운항비(억 원)** 를 수정할 수 있다.
- 저장할 때마다 **마스터 버전**이 1 증가한다.
- 입력값이 잘못되면 오류 목록을 보여 주고 저장하지 않는다.
- 앱 최초 실행 시 기본 마스터 데이터가 자동으로 들어간다.

### 3.3 주문 시뮬레이션
- 나라별 주문 수량(K)을 입력하면 서버가 경로안 **3개**를 계산한다.
  - 운항비 최소 (`COST`)
  - 가장 빠르게 (`FAST`)
  - 가까운 곳부터 (`NEAR`)
- 각 경로안은 총 소요일, 생산비, 운항비, 총비용과 선박별 왕복·기항 일정을 포함한다.
- 결과는 지도 애니메이션과 일정표로 보여 준다.
- 입력 검증: 나라별 수량은 0 이상, 총합은 1K 이상 100,000K 이하.

### 3.4 주문 확정
- 시뮬레이션 결과 중 경로안 하나를 골라 메모(최대 1,000자)와 함께 확정한다.
- 서버는 클라이언트가 보낸 계획을 믿지 않고 **같은 입력으로 다시 계산**한다.
- 시뮬레이션 시점의 마스터 버전과 현재 버전이 다르면 확정을 거부한다(HTTP 409).
- 확정된 주문은 당시의 마스터·주문·계획 전체를 JSON으로 보존한다.

### 3.5 주문 목록·상세·상태 관리
- 주문 목록을 최신순으로 보여 주고, 상태별로 필터·건수 집계를 제공한다.
- 상세 화면에서 저장된 계획을 다시 재생하고 상태 변경 이력을 보여 준다.
- 상태 흐름: **확정 → 진행 → 완료**. 확정·진행 상태에서는 **취소** 가능. 완료·취소는 종료 상태.
- 취소된 주문은 이력만 남기고 주문 레코드는 삭제한다.
- 화면이 본 버전과 다른 사용자가 먼저 변경한 경우 거부하고 새로고침을 안내한다.

## 4. 시뮬레이션 규칙

1. 0일차에 모든 공장이 동시에 생산을 시작한다. 하루 생산량 = min(하루 최대, 재고 상한 − 현재 재고, 남은 주문).
2. 배는 도착 시점의 재고를 모두 싣는다. 한 나라는 한 척의 배만 방문한다.
3. 한 나라의 방문 횟수 = 올림(주문 ÷ 재고 상한). 마지막 방문 전까지는 재고 상한만큼, 마지막에는 나머지를 싣는다.
4. 여러 번 수거할 때는 한국에 들러 내려놓고 다시 출항한다.
5. 배는 재고가 채워지는 날에 맞춰 가능한 한 늦게 출항한다. 한국 대기 비용은 없다.
6. 생산비 = 수량(K) × 1,000 × 단가. 운항비 = 선박별 항해 일수 합 × 일 운항비.

## 5. 화면과 API

| 구분 | 경로 | 설명 |
|---|---|---|
| 화면 | `GET /login`, `POST /login`, `POST /logout` | 로그인/로그아웃 |
| 화면 | `GET /orders` | 주문 목록 (`?status=` 필터) |
| 화면 | `GET /orders/new` | 주문 추가(시뮬레이션) |
| 화면 | `GET /orders/{id}` | 주문 상세 |
| 화면 | `POST /orders/{id}/status` | 상태 변경 |
| 화면 | `GET /master`, `POST /master` | 마스터 데이터 조회/저장 |
| API | `GET /api/master` | 현재 마스터 JSON |
| API | `POST /api/simulate` | 경로 3안 계산 |
| API | `POST /api/orders` | 주문 확정 |

## 6. 데이터

- **Factory**: country(PK), maxDaily, stockLimit, unitCost
- **Route**: fromCountry, toCountry, days
- **Setting**(단일 행): shipCount, shipDailyCostWon, masterVersion, lockVersion
- **Order**: confirmedAt, createdBy, totalK, routeType, routeLabel, totalDays, productionCost, shippingCost, totalCost, status, memo, planJson, version
- **OrderStatusHistory**: orderId, fromStatus, toStatus, changedBy, changedAt

기본 마스터 값:

| 나라 | 하루 최대(K) | 재고 상한(K) | 단가(원) |
|---|---:|---:|---:|
| 중국 | 400 | 4,000 | 700 |
| 일본 | 800 | 2,000 | 900 |
| 베트남 | 200 | 10,000 | 550 |
| 인도네시아 | 300 | 7,000 | 450 |

선박 3척, 1척 1일 운항비 1억 원. 항로 일수는 한국–중국 1, 한국–일본 2, 한국–베트남 5, 한국–인도네시아 7, 중국–일본 2, 중국–베트남 4, 중국–인도네시아 6, 일본–베트남 5, 일본–인도네시아 7, 베트남–인도네시아 2.

## 7. 비기능 요구사항

- 별도 DB 설치 없이 실행된다. 파일 기반 H2(`./data/battery`)를 쓰고 스키마는 자동 생성한다.
- 동시 수정 보호: 마스터는 버전 번호, 주문은 JPA 낙관적 잠금으로 충돌을 감지한다.
- 포트는 Spring Boot 기본값 8080. 다른 포트가 필요하면 `server.port`로 바꾼다.
- 템플릿 캐시는 꺼져 있어 개발 중 수정이 즉시 반영된다.
