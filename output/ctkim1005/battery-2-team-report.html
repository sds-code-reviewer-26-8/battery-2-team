해외 4개국 배터리 공장의 생산과 한국행 선박 운송을 시뮬레이션해 최적 경로를 고르고, 주문을 확정·관리하는 웹 시스템

개요

중국·일본·베트남·인도네시아 4개국 공장에서 배터리를 생산하고, 보유 선박으로 한국까지 운송하는 과정을 일 단위로 시뮬레이션하는 시스템입니다. 사용자가 나라별 주문 수량(단위 K)을 입력하면 서버가 운항비 최소 / 가장 빠르게 / 가까운 곳부터 세 가지 경로안을 계산해 총 소요일과 생산비·운항비를 비교해 보여 줍니다.

마음에 드는 경로를 고르면 주문이 확정되고, 이후 확정 → 진행 → 완료의 상태 흐름을 따라 관리합니다. 공장 생산 능력, 단가, 항로 일수, 선박 수 같은 마스터 데이터는 화면에서 수정할 수 있으며, 시뮬레이션 이후 마스터가 바뀌면 확정을 거부하는 버전 검사가 들어 있습니다.

단일 계정 로그인으로 보호되는 사내용 도구이며, DB는 파일 기반 H2를 사용해 별도 설치 없이 실행됩니다.

주요 기능

주문 시뮬레이션

나라별 주문 수량을 입력하면 3가지 경로안(비용·속도·근거리)을 계산하고, 지도 애니메이션과 일정표로 보여 줍니다.

GET /orders/new · POST /api/simulate

주문 확정

선택한 경로로 주문을 저장합니다. 서버가 같은 입력으로 재계산하며, 마스터 버전이 다르면 409로 거부합니다.

POST /api/orders

주문 목록 / 상세 / 상태 변경

상태별 필터와 건수 집계, 상세 화면에서 저장된 계획 재생과 상태 변경 이력을 제공합니다. 낙관적 잠금으로 동시 수정을 막습니다.

GET /orders · GET /orders/{id} · POST /orders/{id}/status

마스터 데이터 관리

공장별 일 최대 생산량·재고 상한·단가, 항로 일수, 선박 수와 일 운항비를 수정합니다. 저장할 때마다 마스터 버전이 올라갑니다.

GET /master · POST /master · GET /api/master

로그인

세션 기반 단일 계정 로그인. /login과 정적 자원을 제외한 모든 경로를 인터셉터가 보호합니다.

GET /login · POST /login · POST /logout

화면 / API 흐름

컨트롤러는 AppController 하나이며, 화면(Thymeleaf)과 JSON API를 함께 제공합니다.

시뮬레이션 레코드 (DB 저장 없음)

Master는 마스터 데이터 스냅샷(버전, 선박 수, 일 운항비, 공장 파라미터, 항로)이고, Plan은 경로안 하나로 ShipPlan(선박별) → Trip(왕복) → Stop(기항지: 도착일, 출발일, 적재량) 계층을 가집니다. StoredPlan은 이 넷을 묶어 주문의 planJson에 저장되는 형태입니다.

핵심 규칙

Planner가 주문 수량으로 경로 3안을 계산합니다. 소스 Javadoc에 적힌 규칙을 옮기면 다음과 같습니다.

  • 0일차에 모든 공장이 동시에 생산을 시작한다. 하루 생산량 = min(하루 최대, 재고 상한 − 현재 재고, 남은 주문).
  • 배는 도착 시점의 재고를 모두 가져간다. 한 나라는 한 척의 배만 방문한다.
  • 한 나라의 방문 횟수 = 올림(주문 ÷ 재고 상한). 마지막 방문 전까지는 재고 상한만큼, 마지막에는 나머지를 싣는다.
  • 여러 번 수거할 때는 한국에 들러 내려놓고 다시 출항한다(왕복을 나눈다).
  • 배는 재고가 채워지는 날에 맞춰 가능한 한 늦게 출항한다. 한국에서 대기하는 비용은 없다.
  • 운항비 최소(COST)와 가장 빠르게(FAST)는 나라들을 선박 수 이하의 묶음으로 나누는 모든 경우와 왕복 구성 패턴을 열거해 각각 운항비·총 일수가 최소인 후보를 고른다.
  • 가까운 곳부터(NEAR)는 한국에서 가까운 나라를 차례로 배에 돌려 가며 배정하고, 왕복마다 가까운 나라부터 방문한다.
  • 생산비 = 수량(K) × 1000 × 단가, 운항비 = 선박별 항해 일수 합 × 일 운항비. 총비용은 둘의 합.
  • 입력 검증: 나라별 수량은 0 이상, 총합은 1K 이상 100,000K 이하.
  • 확정 시 서버가 같은 입력으로 다시 계산하며(클라이언트 값은 믿지 않음), 시뮬레이션 때의 마스터 버전과 다르면 409 Conflict로 거부한다.
  • 상태 변경 시 화면이 본 version과 다르면 "다른 사용자가 먼저 변경했습니다"로 거부한다.
